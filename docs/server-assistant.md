# 服务器助手配置

## 基础配置

生产环境需要 PostgreSQL 和两个服务器助手密钥：

```text
DB_URL=jdbc:postgresql://数据库地址:5432/ai_platform
DB_USERNAME=数据库用户
DB_PASSWORD=数据库密码
SERVER_ASSISTANT_ACCESS_TOKEN=页面访问口令
SERVER_CREDENTIAL_MASTER_KEY=32字节Base64主密钥
```

主密钥可使用 `openssl rand -base64 32` 生成。它不会写入数据库；丢失或更换后，已经保存的密码和
私钥无法解密，需要在页面逐台重新录入。

## 添加服务器

进入 `/server/assistant/`，打开“服务器配置”，展开“连接配置”后填写：

1. 名称、地址、SSH 端口和用户名。
2. 用户名加密码，或用户名加私钥。凭据提交后会加密，重新编辑时留空表示不修改。
3. `ssh-keyscan` 输出的完整主机公钥记录。非 22 端口的主机格式通常为 `[host]:port`。
4. 保存后使用“测试连接”单独验证认证与主机密钥，不会执行远端命令。

页面内置了密码、私钥、私钥口令和主机公钥记录的获取指引。私钥必须粘贴包含起止标记的完整内容；私钥口令是
生成该私钥时设置的保护密码，没有则留空。`ssh-keyscan` 的结果必须通过云厂商控制台或服务器控制台核对指纹，
不能把网络扫描结果直接当作可信身份。

## 配置命令

新服务器保存成功后会自动添加“系统概览、CPU 与内存、磁盘使用、高资源进程、最近系统告警、Docker
容器状态”六个常用只读命令，不需要逐条录入。已有服务器可以在命令区点击“补充常用命令”；该操作
只补充缺少的同名命令，不会覆盖已经修改过的配置，也不会重复创建。

每条命令都属于一台服务器，并包含名称、用途、命令模板、参数定义和风险等级：

- 普通：模型按需直接执行，适合 `uptime`、`free -m`、状态和只读日志查询。
- 危险：只生成确认选项，适合重启、部署、修改配置或其他会改变状态的命令。

固定命令区支持名称、用途和命令文本搜索，也支持单条或批量启用、停用和删除。停用表示该命令不会进入提供给
模型的工具目录，助手看不到也不会主动选择它；它不修改 Linux 账号权限，也不是绕过服务端审批的执行开关。

日常任务不再要求先新增命名命令。助手会以 ReAct 方式提出“工作目录 + 临时命令”：服务端能按白名单证明
只读时直接执行并把结果交还模型；含写操作、Shell 控制符或其他无法证明只读的内容一律暂停，在回复下方显示
审批卡片。临时命令不会写入数据库，也不会因为路径或参数变化产生重复配置。

临时命令审批卡片支持“执行一次”“本对话允许此命令”“取消任务”和“提交补充”。对话内放行只匹配完全
相同的服务器、工作目录和命令文本，不使用命令前缀或参数通配；执行成功后才生效，删除对话或修改服务器配置
即失效。补充说明会拒绝当前命令，并通过一次性续跑凭证恢复同一任务，让模型按新限制继续规划。

只有用户明确要求把操作保存成长期快捷方式时，助手才生成名称、用途和参数化命令模板，并显示“添加命令”
选项。用户确认前不会写入数据库，确认后也只添加到当前对话选择的服务器，不会同步到其他服务器。

确认添加普通命令后，页面会使用服务端签发的一次性续跑凭证恢复同一对话，助手会重新读取命令清单并继续
原任务，不需要用户再发一条“继续”。添加危险命令只代表允许助手选择它，续跑后实际执行时仍会出现第二个
“执行”确认选项；确认执行后，真实输出也会回到同一对话供助手继续分析。确认和取消既可点击按钮，也可
直接回复“执行”或“取消”，两种交互会消费同一个服务端一次性操作。取消添加或取消执行会追加明确的
结束消息，不再调用模型。手动新增、编辑和删除命令的入口继续保留，方便精确维护。已经保存的固定命令仍以配置的
SSH 用户身份运行；Linux 拒绝执行时，需要在服务器侧为这个账号授予对应权限。必须遵循最小权限原则，
例如只为确实需要的固定操作配置精确的免密 sudo 规则，不要授予不受限的 `sudo ALL`。

命令模板使用 `{{name}}` 表示可变参数，占位符必须独占一个 Shell 参数。参数定义是 JSON 数组，支持
`PATH`、`ENUM`、`INTEGER`、`TEXT`：路径必须声明 `allowedRoots`，枚举必须声明 `allowedValues`，整数可设置
上下限，文本可设置长度和正则。服务端校验后统一做 POSIX Shell 单引号转义，同时拒绝路径 `..` 越界、
换行和空字节。因此 `ls -la {{path}}` 可安全复用 `/var/log/nginx`、`/srv/apps/demo` 等不同路径，无需每个
路径新增一条命令。

## 自定义模型提供方

点击左下角用户资料区，在弹出菜单进入“模型设置”，可新增自定义提供方，填写 Provider ID、显示名称、API 地址、API 协议和 API 密钥。
提供方与服务器无关，是全局配置，保存后所有服务器对话都可使用。支持
`openai-completions`、`openai-responses`、`anthropic-messages` 三种配置协议；可以在保存前测试连接，并从
提供方的 `/v1/models` 模型目录导入模型，也可以逐行手动添加。API 密钥使用与 SSH 凭据相同的
AES-256-GCM 主密钥加密，读取接口只返回“已配置”状态。

当前服务器工具对话完整支持 `openai-completions` 和 `anthropic-messages`。项目使用的 Spring AI 1.1 尚未提供
OpenAI Responses API 的工具调用适配，所以 `openai-responses` 目前只开放连接测试和模型目录，模型选择器会明确
标记且禁选，避免运行时以模糊的网络错误失败。

模型和推理等级放在消息输入框右下角，模型按“提供方 → 模型”级联选择，推理等级使用分段滑块并按对话保存；
确认命令后的自动续跑会沿用同一选择。模型接口显式返回的
`reasoning_content`、常见兼容网关的 `thinking/reasoning_details`、Anthropic thinking 或显式 `<think>` 块会
单独通过 SSE `reasoning` 事件发送，在页面“思考过程”中默认折叠展示并保留上下箭头。折叠状态下仍会显示实时
字数、最新片段和活动标记；没有从接口返回的内部推理不会被伪造或展示。若请求了推理但提供方只返回正文，服务端
会记录 `reasoningChars=0` 和一条 WARN 日志，便于检查模型能力与协议。

以 OpenCode Go 为例，DeepSeek V4 Flash 使用 `openai-completions`，基础地址填写
`https://opencode.ai/zen/go`（聊天路径保持 `/v1/chat/completions`），模型 ID 使用 `deepseek-v4-flash`。
推理等级会作为 `reasoning_effort` 发送；只有上游实际返回独立 reasoning 时页面才显示思考折叠区。
前端每 60ms 合并流式碎片再重绘，避免几个字符一次的 Markdown 全量渲染造成卡顿。只有用户停留在消息底部时
页面才自动跟随输出；手动上滚会解除跟随并显示“回到最新消息”按钮。提问达到 6 条后，桌面宽屏右侧显示可跳转
的本次提问目录。

服务端不会再使用 Servlet 的绝对 SSE 时长切断长回答，而是只在连续 10 分钟没有任何模型事件时超时。日志会记录
请求开始、首包耗时、完成耗时、正文/推理字符数、模型错误和工具调用，但不会打印用户消息、模型正文、API 密钥或
SSH 凭据。

服务器助手由 Spring AI `ChatClient` 的流式工具调用循环驱动：模型可以在一轮请求中反复“判断 → 调临时或固定
工具 → 读取结果 → 继续”，遇到非只读操作时由服务端状态机暂停，用户选择后恢复同一模型任务。它是个人使用的
轻量 ReAct Agent 基座，不是脱离请求持续运行、拥有无限制 Shell 的常驻进程。

## 对话与数据边界

新建对话时先选择服务器。同一对话固定绑定这一台服务器，切换选择会自动新建对话。聊天当前只保存
在浏览器本地；“近期对话”悬停后可用单个 × 删除，管理模式也支持全选或多选删除。删除时先由服务端同步清理该对话的模型记忆、
服务器绑定、待确认执行、待确认命令提议和未消费的续跑凭证，再删除浏览器记录；全部删除后会自动创建一个空白对话。数据库仅包含
`server_assistant_server`、`server_assistant_command`、`server_assistant_model_provider` 和
`server_assistant_model` 四类配置。
